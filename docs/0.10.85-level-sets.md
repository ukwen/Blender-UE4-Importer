# 0.10.85-dev — saved project level sets and partition ownership

The original four ShooterSam UE5.6 World Partition maps explicitly save bIsPartitioned, bUseExternalActors and bUseActorFolders = true. Each partition belongs to the saved WorldSettings export, and its EditorHash and RuntimeHash are checked by exact export ownership. All save bEnableStreaming = false. Verified original external actor packages: ThirdPerson 65, Combat 138, Platforming 144, SideScrolling 118 (465 total; zero ownership errors). ThirdPerson uses WorldPartitionRuntimeHashSet; the other three WorldPartitionRuntimeSpatialHash. The other two valid World maps have no partition object; one extra .umap is not a World and is rejected. Candidate LevelStreaming/LevelInstance/PackedLevelActor exports and streaming-related World fields are inventoried conservatively; no positive candidates in these four maps. No native cell loading, data-layer visibility evaluation, streaming transforms or level instance reconstruction is claimed. Generic map references do not establish composition.

In the project panel, scan the project, check desired map rows and press **Import Checked Levels (Separate)**. Selected supported maps are transferred through the existing full-scene importers in an atomic operation. The resulting project collection holds one independent level collection per map; only the first is initially visible. Select an imported map and press **Show Selected Imported Level** to switch visibility. Original coordinates, independent worlds/optional previews, active user camera and world are preserved. Visibility switching does not apply a sky world automatically. Existing scene objects remain unchanged; no guessed relative placement. Unsupported or duplicate selected maps are refused, and an exception on a later level rolls back all newly created IDs. Reports record active level. This is deliberately separate from native streaming assembly; existing level imports are not moved or reused.

Material safety: malformed child override flags now block inherited values for that property rather than silently taking the parent's value. Material cache revision updated. External actor folder root may not escape the project's Content directory via symlink. Missing active values, arbitrary float4 and absent material functions remain unresolved; fog is still a bounded, uncalibrated preview.

Actual Blender 4.2.4 acceptance on original ThirdPerson and TestLevel through registered operators: 75 objects, 54 meshes, one rig, two lights, one camera; each level has a persistent layout report, exclusive visibility, exact world matrices after reopening (max error 0), unchanged original user camera/world, duplicate refusal and full rollback after injected second-level failure (Combat first stage). Python baseline 86 passed, current 91 passed, both 23 skips, zero failures. Single-level, original material-instance and fog regression passed; isolated install and three mesh job reuse passed. No new assets.
