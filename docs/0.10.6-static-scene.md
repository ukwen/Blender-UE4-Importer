# 0.10.6-dev: static scene geometry integration

New Unreal sidebar action Reconstruct Static Geometry. Resolves project and optional engine content by canonical package path, attempts native static mesh import without materials, shares decoded meshes across actors, keeps missing/unsupported/failed dependencies as tagged empties. Per-package and per-actor counts and diagnostics are stored in a Blender Text datablock, referenced by the result collection's UE_report property. Existing legacy Import Selected Map action is unchanged. Material override names retained as metadata; no material reconstruction. Not a UE5, Blueprint, terrain, foliage or skeletal scene importer.

Direct Blender 4.2.4 tests with the supplied partial project: 562/562 static actors parsed, 562 distinct dependencies, no skipped actors or unresolved parents. All 562 dependency files are absent from the partial fixture. The genuine rope file is not referenced in Overview. Matched project report paths: 561 of 562 are in the user's project inventory, remaining /Engine/BasicShapes/Plane requires engine content. No actual Overview mesh geometry accepted. Controlled routing test assigned the real rope to two test actors and verified shared mesh datablock, one decode, 32 vertices, 60 faces, two UV layers, exact matrix_basis equality against the decoded map layout. The surrogate collection was deleted before saving. Separate Blender process reopened the 562-empty diagnostic scene and confirmed persisted JSON. Six resolver unit tests and registration/browser smoke scripts passed. New source files match executed copies by checksum; local mesh reader differs slightly from committed 0.10.5, so complete current-head regression remains outstanding.

Reproduce with GOBLIN_CONTENT pointing to the partial fixture and a Goblin.uproject two levels above it. Run Blender -b --factory-startup --python-exit-code 1 --python tests/blender_static_scene.py.
