# 0.10.70-dev — authored root translation and external pose validation

In Blender, select an imported native armature without existing animation, choose File > Import > UE4.27 / UE5.6 Editor Animation, and select **Authored root translation > In-place + trajectory**. For the verified UE5.6 editor FK profile, this requires the serialized root-motion flag, a single named root hierarchy, and a matching skeleton (explicit same-package subset where necessary). It holds the root translation at its first authored sample, retaining all authored rotation and scale. The original relative displacement, including vertical travel, is keyed in three editable armature custom-property channels `UE_authored_root_delta_m` (Blender armature axes, meters), and the unmodified source trajectory and first-sample origin are stored on the Action. The trajectory does not drive the armature object; it is usable for editing or separate locomotion reconstruction. It is meaningful only while the corresponding in-place Action is active. Other Actions do not key that custom property and may retain its previous values. Choose Original instead to retain all authored travel in the skeleton. The existing explicit additive/retarget authored-preview requirement is unchanged. No Unreal root-lock behavior, runtime extraction, root rotation delta, character movement, retargeting or additive evaluation is claimed.

Source animation SHA-256, package/name, sample timing, serialized root flags (including presence vs absence and normalized scale if present) are recorded for new Actions. Previously imported Actions need reimport to acquire these fields. The legacy default behavior is unchanged.

## External reference comparison

`animation_reference.compare_reference(arm, scene, reference)` checks every source sample and target bone against externally supplied Unreal component-space transforms. `tools/blender_compare_animation_reference.py` runs in a saved Blender scene; activate the original imported Action, then set `UE_POSE_REFERENCE` to the JSON, `UE_POSE_ARMATURE` to the Blender armature object name and `UE_POSE_REPORT` to the output JSON. Run `blender -b input.blend --python-exit-code 1 --python tools/blender_compare_animation_reference.py`. It restores the current frame and rejects mismatched SHA-256, skeleton, animation name, incomplete or invalid samples, in-place Actions and constrained/driven rigs. It reports maximum position error in meters and 3x3 basis-element error; both tolerances are 0.0001. No match can authenticate the reference producer.

JSON contract: `schema` = `ue_component_pose_reference_v1`; `provenance` = object with `kind` (`engine_evaluated` or `authored_fixture`) and nonempty `description` (include UE version, mesh, playback settings, root extraction, additive and retarget configuration for an engine reference); `source_sha256` = original .uasset digest; `skeleton_package` = exact source `/Game/...` identity; `animation_name` = source AnimSequence object name; `space` = `unreal_component_cm_column_vector`; `bones` = all target bone names exactly once; `frames` = one object per source sample from 0 through N-1 in order, with integer `sample` and `matrices` array in bone-name order. Each matrix is 16 finite numbers in row-major storage, column-vector transform convention, translations in centimeters, final row [0,0,0,1]. Unreal's row-vector FMatrix representation must be transposed before writing this schema. Engine evaluation and reference export remain external prerequisites; this tool does not launch Unreal or generate engine truth. It compares the imported Action, not a runtime animation blueprint.

## Acceptance

Original ShooterSam: 62 root-motion-enabled sequences inventoried. Six imported source/in-place pairs (267 source frames, 89/161 bones), at 24 fps with source RateScale, including diagonal walk, vertical fall, dash, attack, retarget-source and additive-authored previews. Every bone/sample compared before and after saving/reopening; 46,098 skinned vertices compared on three sampled poses of three clips. Worst path error 0 m at Blender float precision, maximum recomposition matrix element error 1.05e-5, maximum skin difference 0.00699 mm. Refused non-root-motion clip and unrelated custom property. External comparator: 4,183 bone/sample matrices independently reconstructed from original serialized Euler data (not engine-evaluated); 0.00504 mm maximum position difference and 9.96e-6 basis error. A deliberate 1 cm perturbation failed tolerance and a wrong source hash was rejected. Full engine runtime equivalence remains unverified, as does new Windows acceptance.
