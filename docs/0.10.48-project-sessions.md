# 0.10.48-dev — saved-scene sessions and asset selection

## Workflow (Blender 4.2.4)

1. Open the Unreal sidebar and set the `.uproject` file. Choose All maps, Selected map or Geometry folder. Select the original import options (including the cooked layout profile).
2. Optional: enter an asset path substring, refresh the asset job list, enable **Use checked jobs only**, and select exact jobs. All/None controls operate on the displayed catalog. Refresh after changing project, scope or filter. Run **Dependency Preflight** to inspect the selected job closure and missing packages in the Text Editor.
3. Optional: save the working `.blend` and enable **Save recovery copy before batch**. The importer creates a distinct full Blender backup beside it. No existing file is overwritten and the active file path is unchanged. Open that copy manually to restore the pre-batch state if needed.
4. Run **Run / Resume Batch Import**. Escape stops after the current native job. Save the working `.blend` after stopping. Reopen the saved file and run the same import settings again; completed owned collections are reused and the rest are processed. Widening the job selection is allowed. Completed maps may have diagnostic missing actors; reuse does not imply visual equivalence.

## Safety and limitations

A completed job owns one collection with a stable project/path identity, source SHA-256 fingerprint, relevant option fingerprint, member tokens and serialized result. The source fingerprint is intentionally conservative (all project package files and sidecars, project descriptor, and known directly reachable engine packages). Changing source bytes or options blocks an owned job instead of silently overwriting animator edits. Moving or deleting owned objects, or creating duplicate owned collections, blocks reuse; review the prior collection and its objects manually. Untagged legacy imports are not deduplicated. Scene membership is checked, not mesh edit equivalence. Source files should stay unchanged during a running batch. Recovery requires saving the working .blend; unsaved changes are not automatically recovered after a crash.

UE4 object versions 508 and 522 now inspect the bounded package-summary soft-reference table (FString and FName respectively). These edges are distinct from import-table references. UE5 and other unsupported soft tables are marked unknown; neither the summary nor import tables imply runtime Blueprint dependencies, dynamic string paths, or complete plugin mount coverage. No Blueprint execution is attempted.

On a failed job, the runner removes new top-level Blender IDs across data types. It does not attempt to reverse arbitrary mutations of existing datablocks. The opt-in full pre-batch recovery copy provides a manual restoration path, not automatic transactional rollback. The UI modal path now uses Blender 4.2's generic TIMER events with a monotonic throttle (Event has no `timer` attribute). Escape cancellation is cooperative, not an interrupt inside a decoder.

## Acceptance

See `tests/blender_project_session.py`, `tests/blender_job_catalog.py`, `tests/blender_recovery_copy.py` and `tests/blender_session_modal.py` (the last requires a real GUI Escape press). Western Frontier: resume one map from a saved file, reconstruct the second, and rerun both with zero new objects; preserve 2,316 static actors, 462 foliage instances and 36 skeletal actors. Vehicle set: cancel after two, save/reopen, resume 11 remaining jobs to 13 original rigs and automatic physics; actual GUI Escape stops at the first native job. Source-change, setting-change, damaged membership and injected failure checks refuse unsafe reuse or clean up new IDs. Catalog test imports exactly two checked native vehicle jobs. Recovery-copy test reopens the independent copy and confirms the active original is untouched.
