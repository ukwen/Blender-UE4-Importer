## Actual Linux desktop acceptance

On isolated Xvfb 1440x1000 with software rendering, Blender 4.2.4 was run without `-b`, with isolated preferences disabling the splash. `tests/blender_ue56_desktop.py` sets up the project and invokes the real registered operators. `tests/desktop_x11_driver.py` selects the Unreal tab using XTEST, reads the clipboard via an external X11 selection client, sends an actual Esc after one map is staged, and captures screenshots. The test checks exact ID rollback, camera/world preservation, a successful modal retry (94 objects, two original maps), and expanded/collapsed panel captures. Initial first-run screenshot showed the splash; corrected setup. Initial driver errors (Xauthority file, screenshot capture, string decoding) corrected. Expanded panel log checked for draw exceptions. This is automated Linux virtual desktop acceptance, not physical Windows/desktop usability sign-off.

`tests/blender_ue56_desktop_recovery.py` and `tests/desktop_recovery_x11_driver.py` withhold one original SM_Cube package in a disposable project copy. Actual X11 Esc dismisses the confirmation without writes, and Return confirms the same reviewed plan, restoring exactly the original SHA-256 while preserving the recovery folder and authoritative source. No new data downloaded.

Run on a **dedicated** virtual display, never the user's interactive desktop. The X11 drivers require python-xlib and Pillow (test-only; no add-on dependency). Example:

```
Xvfb :92 -screen 0 1440x1000x24 -ac +extension GLX
# Separate shell, source verified recovery environment.sh first.
export DISPLAY=:92 BLENDER_USER_CONFIG=/tmp/ue-ui-config BLENDER_USER_SCRIPTS=/tmp/ue-ui-scripts
export LIBGL_ALWAYS_SOFTWARE=1 UE_DESKTOP_DIR=/tmp/ue-ui-result
mkdir -p "$BLENDER_USER_CONFIG" "$BLENDER_USER_SCRIPTS" "$UE_DESKTOP_DIR"
# Isolated test display only. If Xlib needs a file, set XAUTHORITY to an empty test file.
"$BLENDER" -b -t 2 --python-expr 'import bpy; bpy.context.preferences.view.show_splash=False; bpy.ops.wm.save_userpref()'
"$BLENDER" -t 2 --python tests/blender_ue56_desktop.py
# Run concurrently in a second shell on that dedicated display:
python tests/desktop_x11_driver.py "$UE_DESKTOP_DIR"
```

For recovery confirmation, use a fresh UE_DESKTOP_DIR and the two recovery scripts instead. Screen capture uses the X11 root window; the tab coordinate assumes the default 1440x1000 Blender Layout. Inspect logs for draw exceptions. Native Windows, real GPU/driver differences, physical accessibility and sustained multi-window interaction remain unverified. No changes to scene conversion algorithms.
