# 0.10.31-dev: cooked static render mesh profiles

Adds explicit UE4.18 and 4.27 tagged split-package cooked StaticMesh import for bounded single inline LOD profiles. Sequential decoding validates root export extent, render sections, positions, interleaved or separate tangent and UV buffers, index arrays, and material references. Collision data, sockets, opaque post-LOD metadata, external buffers, additional LODs, high precision tangents and full material binding remain unsupported or unverified. New operator is separate from existing editor and map import paths. Vertex colors are parsed for the accepted layout but not validated on these genuine samples. No claim of general cooked static compatibility.

Genuine Matya-Uasset-Samples SM_Worm for UE4.18 and 4.27: both 640 vertices and 572 triangles; decoded positions, faces, UVs, slots and material references exactly equal. Blender geometry/UV correspondence, custom normals, source tangent attributes, placeholder material identity, wrong profile/class and truncated sidecar refusal, save/reopen passed. 14 Python unit tests and four Blender 4.2.4 scripts (cooked static, smoke, native skeletal 4.27, controlled raw animation) passed. No sample assets committed. This commit builds on the exact tested 0.10.30 commit, even if GitHub branch-update service remains unavailable.
