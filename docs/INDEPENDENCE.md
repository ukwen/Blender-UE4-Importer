## 0.10.98 — project paths and classic property records

`project_paths.py` implements the project and engine mount contract using pathlib/JSON, independent of uasset and Blender. All production project-resolution consumers now import it directly; legacy UProject remains an alias only. Map inventory can run via `tools/inspect_saved_project.py` without Blender. Explicit descriptors disambiguate colocated projects, malformed metadata and unsafe path components are rejected, and resolved paths must remain within the content root. Native Windows registry discovery was not tested.

`ue4_property_records.py` implements immutable classic header records, preserving native payload boundaries and opaque container contents, based on permitted MIT UAssetAPI PropertyData.cs and original UE4 522 root fixtures. Animation and skeleton tag consumers use the compatibility view; UE4 animation export routing no longer imports UAsset or the inherited material resolver. Controlled animation boundary passed, but original UE4 raw-animation parity was not rerun (matching fixture absent locally). General UProperty/Properties decoding and legacy geometry, material and map paths remain inherited. No legal clearance or complete clean-room claim.
