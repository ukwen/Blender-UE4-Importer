# 0.10.1 development checkpoint

Blender 4.2.4 LTS Linux x86-64 (build e41b0e807a59) launched from the user's Library archive. Native project browser is registered in the add-on entry point. In the 3D View press N, choose Unreal, select a .uproject, Scan Unreal Project, select a map, and Import Selected Map. Content maps are discovered directly; external actor/object packages are excluded rather than treated as standalone maps. UE5 and World Partition are not supported by the legacy importer.

Targeted Blender tests using synthetic project descriptors and empty map fixtures passed: scan and sorting, external actor exclusion, selected-map routing to a mock legacy reader, missing project rejection, registration/unregistration/re-registration. Blender APIs for Principled BSDF, material surface methods, SPHERE/VOLUME light probes and custom mesh normals were also verified. This is not a full native import test or a complete add-on registration test. Direct Git clone failed DNS; the browser was exercised as a standalone module locally and committed via the GitHub connector. No genuine Unreal project fixture was used. Original master unchanged.

Run browser tests: blender -b --factory-startup --python-exit-code 1 --python tests/blender_project_browser.py

Full addon smoke and genuine UE4/UE5 asset regression remain acceptance gates. No distributable release; licensing unresolved.
